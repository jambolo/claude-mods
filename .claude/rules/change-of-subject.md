# change-of-subject

- The judge and the dialogs run inside the `prompt.submit` hook, which holds the prompt while they do. `$.model.complete` and `$.ui.ask` are allowed there; `$.command.run`, `$.prompt.submit` and `$.session.compact` are not — the engine refuses each of them from a hook holding a turn. So a chosen command runs from a `$.clock.after` timer, after the hook has answered `{ drop }`, and the prompt it displaced is sent again from there.
- `$.ui.ask` is the pop-up: it is raised as a call to the AskUserQuestion tool, so a test stands in for it with `on('tool.call', { tool: 'AskUserQuestion' }, ...)` answering `{ result: { answers: { [question]: choice } } }`. At most four options, a header of at most 12 characters, and a person can always type their own answer — anything that is not one of the offered options is taken as "leave my prompt alone".
- A typed slash command and a `#` memory line both reach `prompt.submit` with `origin.kind === 'composer'` — measured against 2.1.299 in the terminal, where dropping the line stopped the command from running — so the origin cannot tell them from a prompt and `COMPOSER_LINE` in `model.ts` is what keeps them away from the judge. A `!` shell line does not reach the hook from the terminal; it is named in that guard for a surface where it might.
- A command's own turn does reach `turn.complete`, so the answer to `/release-notes` is remembered as a `claude` line even though the command line itself was never judged. A subagent's answer still is not.
- `act` holds the displaced prompt before the command runs, so a `/clear` that tears the session down still has it. `/clear` and `/compact` make room, so the prompt follows them (`after`); `/btw` is handed the prompt as its own question, so it comes back only `if-it-fails`.
- The test world queues what the engine would do: a `verdicts` entry of `'throw'` is a judge that is not there and an `answers` entry of `'throw'` a dialog the person dismissed, `failing` names a command the engine will not run, `unsendable` a prompt it will not take back (the box catches it), and `pending` holds a command open — `/clear` holds until the session it tore down has been replaced, which is what leaves the hand-back to `session.start`.
- Only a prompt a person typed is judged: the engine calls a typed or queued one `unclassified`, and a client's own box `composer`. A prompt this mod sends again carries a `plugin` origin, so it cannot be judged twice; `sent` guards the same loop a second way.
- `send` passes `asUser: true`. Without it the engine frames a plugin's prompt as `The <plugin> plugin sent a message:` and explains to Claude that it starts the turn in the person's place — measured against 2.1.299; with it the prompt reads as the person's own. The dialogs name no reason for the same reason: the pop-up is a question, not a case, and the judge's words live in `/change-of-subject`. Both dialogs offer the same four options (`ASIDE_OPTIONS`, `PHASE_OPTIONS` in `model.ts`), the verdict's own first: `/btw`, `New session`, `Compact first`, and the denial. With four the engine's limit, there is no `Continue here anyway`: a typed Other or a dismissal leaves the prompt where it is with no word on the verdict.
- `decide()` swallows everything and answers `''` for "let it through". Watching a prompt must never cost the person the prompt, so every failure — no judge, a slow judge, an unreadable verdict, a dismissed dialog — ends with `next(e)`.
- The session record (`log`) holds only prompts that reached the session and the main loop's answers, never a subagent's. A prompt handed to `/btw` never enters it, because it never entered the session.
- One state value, `judge` (`off`, `haiku` or `jev`), says whether prompts are watched and by whom; `on` is `haiku`, so after `off` the mod comes back with the default judge. It lives in `$.state`, which lasts until Claude Code exits: the `session.end` handler leaves it alone on `clear`, unlike the record of the session, so a `/clear` keeps the judge, and every start of Claude Code watches, judged by Claude Haiku.
- Anything that takes `$` lives in `register.ts`, never in an imported module: Claude Code 2.1.295 (what the desktop app's Code tab runs) refuses a hooks module that passes `$` into a function imported from another file ("`$` is followed only into a function declared in this same file"), though 2.1.301 allows it. Only the pure `model.ts` and `teach.ts` are imported. So the judges and the labels sit in `register.ts` under their own comment headings, and `claude plugin validate` and the tests do not catch a regression: check by running `--plugin-dir change-of-subject -p "/change-of-subject"` under 2.1.295 (`npm install @anthropic-ai/claude-code@2.1.295` into a scratch folder).
- The judges are behind `judgeWith($, by, ...)`. It is a call rather than a table of judge functions because `claude plugin validate` refuses `$` read out of a value (`JUDGES[by]($, ...)`): `$` must be spelled at each call site.
- `jev` swaps the judge for TypeSafe AI's Jev (`judgeWithJev`). It is one Choice question over `$.http.fetch`, the briefing as its `state`, its options the verdicts themselves (`MEANINGS`, the same descriptions the Haiku prompt is built from). Jev returns probabilities, not words: `readJev` gives its `pick` and how `sure`, with no reason, and "prefer same when close" is `gate` in `teach.ts` (`DEFAULT_SURE.jev`, 0.7, until labels set a bar). `$.http.fetch` takes no timeout or signal, so the judge races it against a `$.clock.after` timer; `JEV_TIMEOUT_MS` stays under the hook's 10s budget because how the engine counts that wait is undocumented.
- A judge that gives no answer (Haiku: the call rejects or `isAnswered` is false; Jev: no key (`isKey`: unset or empty), the request fails, times out, is refused, or its body holds no verdict, or no probability or confidence between 0 and 1 for it) returns `failed(why)`: verdict `same` with a `failure`. `decide()` lets the prompt through, does not count it in `judged`, keeps it in `last` for the report, and raises a `$.ui.toast` only when the failure differs from `last`'s, so a refused key is told once, not on every prompt. A Haiku reply that names no verdict is an answer, not a failure: it stays `NO_VERDICT`.
- Labels (`Example` in `types/index.d.ts`) live in `$.store` through the labels section of `register.ts`: `local:<$.session.root()>:examples`, `:lessons:<judge>` and `:calls:<judge>` (the judge's `Calibration`) for a project, `user:examples`, `user:lessons:<judge>` and `user:calls:<judge>` for every project, `learn` for where new labels go (`learning`, default `local`), and `sizes` for how large each label key is and when each project was last opened. Every label write goes through `put` or `drop`, which record the key's size (`sizeOf`, UTF-8 bytes of its JSON), so `visit`, on `session.start`, reads `sizes` alone: it stamps this project in use and, while all label keys together pass `BUDGET_BYTES` (2 MiB, half the store's 4 MiB), deletes every `KINDS` key, recorded or not, of the projects used longest ago, never this one's. A project is stamped in use at each start, at each write (`measure`), and at most hourly by `use` while prompts come in, so a long session that only judges is never taken for one left. A store with no `sizes` starts an empty record: stores from 1.2.x are not migrated. Labels are trimmed by `keep` (calls borne out before mistakes, oldest first). Nothing is labeled while the judge is `off`, and only `was` while `learn` is `off`. Every store write that reads first (`learn`, `unlearn`, `relearn`, `keepLessons`, `forget`, `promote`, `visit` and the tally writes) runs through `serially`, so two in one process never interleave; only the outermost write takes a turn, and `put`, `drop` and `measure` never do, or a write would wait on itself. Two Claude Code processes can still interleave: the store has no compare-and-set.
- A label is a pop-up answer (`truthOf(choice, said)`: `/btw` is `{ is: 'aside' }` whichever pop-up offered it, since a side question is unrelated to the work and so no phase of it; `Compact first` is `{ is: 'phase' }` whichever pop-up offered it, since an aside takes the work so far to be irrelevant and a compaction keeps it; so on the other verdict's pop-up each is a mistake. `New session` bears out either verdict, since an aside may want more than `/btw`'s one answer, and the denial is `{ not }`; the tally counts the answer right when `bearsOut(truth, said)`; `a typed Other` and a dismissal say nothing) or a `was`. Its `truth` is `{ is }` for an answer that names a verdict or a `was`, and `{ not }` for a denial, which says only what the prompt was not; `bearsOut` answers undefined where the truth cannot say. `isMistake` is a truth that does not bear out the judge's own `pick` (`said`, the verdict the mod acted on, only when it gave none): a right call the bar held back is the bar's mistake, which the tally fixes, not the judge's. Labels from `/btw`, `/clear` or `/compact` run by hand are not kept: Claude Haiku is asked only about pop-up answers and `was`, and a label with no comparison teaches nothing.
- A label carries a `comparison`, one sentence on how the prompt related to its session, in place of the session's lines. Claude Haiku as judge writes it on a second line of its answer for `aside` or `phase` (`readVerdict`, `JUDGE_TOKENS`), so a pop-up answer under Haiku needs no second request. Otherwise (Jev judging, or a `was` with no comparison in the ruling or the label it replaces) the label is kept with its `session` and `explain` has Claude Haiku (`explainVerdict`, `medium`) write the reason and comparison off a `$.clock.after` timer, then drops the session. The judge's own reason is kept when it gave one. A label whose explanation failed waits with its session until `draw` runs `explainWaiting`.
- `ruling` is the last prompt a judge gave a verdict on, the session it saw (`sessionOf`: the anchor first once the log has let go of it), its call, reason and comparison, and the scope its label is in; `/change-of-subject was` unlearns it there and learns the correction in the scope it names. `learnFromPrompt` writes `ruling` before the store, so a write that fails still leaves something `was` can correct, and `unlearn` of a label that was never kept is a no-op. It swallows its own failures, apart from `decide()`'s catch, so a store that fails never changes the choice the person made.
- `teach.ts` is what the judge is taught, all pure: `teachingFor` in `register.ts` reads both scopes and hands `judgeWith` a `Teaching` (the `anchor`; `pastCalls`; the judge's own rules, every project's first) and `gate` the `Bars` from `barsFor`. `teaches`: a call borne out teaches either judge, a mistake only the judge that made it. `pastCalls` ignores the prompt's words: the judge's mistakes first, then this project before every project, then newest, taking the first of each verdict spoken of (`spokenOf`) before the rest; a label with no comparison is never shown. Haiku sees each as prompt, comparison and `<verdict>` or `<rejected>`, with no reason; Jev, from both scopes too, as `examples` and `not` under each verdict's criteria, since its request has no field of its own for either. Every-project labels carry prompts from other projects to Anthropic and TypeSafe; that is documented in the README rather than prevented, since a person who keeps labels for every project means them to teach everywhere. Bars come from each scope's `Tally` per judge and verdict (`types/index.d.ts`), not from the labels: `keep` holds mistakes longest, and a sample trimmed that way drove bars to `HIGHEST_BAR`. `countAnswer` adds each pop-up answer with a `sure` in the scope its label is kept in (`answeredIn`, 5% steps, shrinking in proportion past `CALLS_REMEMBERED`), and `calibrated` finds the lowest step whose calls at or above it are right four times in five. `was` is no fair sample (the person picks what to correct), so it is never counted, with two exceptions: one that turns a pop-up answer around moves it to the other count (`recount`), and one saying a call the bar held back was right reopens the bar down to that call (`reopen`, `reopenedIn`) until `REOPENED_ANSWERS` pop-up answers from that range are in, wherever their labels go. There are no random pop-ups below the bar: without a `was`, a bar too high stays where the tally put it. Claude Haiku answers `<word> <0-100>: <reason>`; a reply without the number is not gated.
- Rules are drawn per judge by `drawLessons` (Claude Sonnet, `high`) off a `$.clock.after` timer once `isDue`: ten of that judge's mistakes newer than its `upTo`. `lessonsBrief` gives each call's comparison, the judge's verdict and reason, and the person's word (`bore it out`, `turned it down`, `said it was`); `LESSONS_SYSTEM` asks for rules about how a prompt relates to its session's work. A drawing that gives nothing still moves `upTo`, so a failing model is asked again only after ten more; `drawing` keeps a scope and judge from being drawn twice at once, and `explaining` a label from being explained twice.
- The files Claude changes come from `tool.call` hooks on Edit and Write (subagents' included, since their edits are the session's work) and ride on the main loop's next `claude` line.
- Tests stand in for the store with `on('store.get')`, `on('store.set')`, `on('store.delete')` and `on('store.keys')` (`isStoreBroken` refuses every write, `w.reads` lists the keys read), and for the project root with `on('session.root')`, `C:/repo`. `on('model.complete')` answers a `sonnet` request from `w.lessons` (recording `w.drawn`), one with `EXPLAIN_SYSTEM` from `w.explanations` (recording `w.explained`, defaulting to `EXPLAINED`), and any other as the judge (recording `w.briefings` and `w.systems`).
- The test kit hands the plugin its own error text for a test hook that throws (`no implementation for model.complete`), not the hook's, so tests match a failure's prefix only. The key is read from `TYPESAFE_API_KEY` by `$.env.get`, and `init.auth` is not used: it carries only first-party credentials. Tests stand in for Jev with `on('http.fetch')` and for the key with `on('env.get')`.
